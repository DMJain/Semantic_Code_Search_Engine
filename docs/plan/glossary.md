# Glossary

## Phase 1
- **Slice**: subset of the corpus that gets vectors and summaries and is the eval scope; marked by `files.in_slice`; frozen at the end of S1 (D-005).
- **Filtered repo**: the pinned Kubernetes checkout after exclusions ([architecture.md#corpus-and-slice](architecture.md#corpus-and-slice)).
- **Chunk**: unit of raw code that is full-text indexed and (in the slice) embedded; rules in [architecture.md#stage-chunk](architecture.md#stage-chunk).
- **Chunk header**: context prepended to a chunk (package, file, signature, top callees/callers).
- **Part**: one piece of a function split at top-level statement boundaries; `part_idx` from 0; every part keeps the signature (D-078). Part 0 starts at its first doc-comment line, where the doc comment is the S1 `doc()` run of `//` lines (D-083).
- **Group chunk**: a struct or interface with its same-file `NewX` constructor, one chunk when the pair fits `GroupMaxTokens`.
- **Oversized statement**: a single statement over `ChunkMaxTokens`; kept whole as its own part and counted. It still embeds (header degraded) while its content fits the request budget less the largest document prefix; above that it fails in both A0 and A1 (D-082).
- **Request budget**: `0.8 x` the smallest embedding `num_ctx` in the registry (1638); chunk content plus header must fit it (D-078, D-082).
- **Degraded header**: a header with callers, callees or signature dropped to fit the request budget; `chunks.header_degraded > 0` (D-082).
- **Zero-chunk file**: a slice file with no chunk; counted by D-080, with or without top-level decls.
- **Residual chunk**: conditional per-file chunk of uncovered top-level const/var/type-alias decls (D-080).
- **Embedding variant**: `chunk_raw` (no header) versus `chunk_header`.
- **Route**: query type decided by the router: lexical, structural or semantic.
- **Fan-out**: running all retrievers and fusing when router confidence is low (also config A4).
- **Rules-only router**: the router with the LLM disabled (`ROUTER_LLM=off`); used by A3n and by Phase 2.
- **RRF**: reciprocal rank fusion of file rankings, k=60.
- **Collapse helper**: the single `internal/retrieve` function that filters to the slice, then de-duplicates files, then cuts to top-k (D-039).
- **Hop**: one iteration of the `/ask` loop (fetch more evidence or answer).
- **Evidence set**: code snippets and symbols collected during `/ask`; citations must fall inside it.
- **Edge resolution**: how a tree-sitter call edge was resolved (D-073): `exact`, `name_only` (a guess; always has a callee), `ambiguous` (one row per candidate callee), or `unresolved` (no callee; carries a reason).
- **Unresolved edge**: an edge with `callee_id NULL` and an `unresolved_reason` (`external`, `no_match`, `unknown_receiver`, `func_value`, `candidates_capped`); kept for recall accounting, never followed by retrievers.
- **Exact (edge)**: resolved with certainty by the source that produced the edge; for `source='gopackages'` (GT) rows every edge is `exact`, so `source` disambiguates (D-077).
- **Skip counters**: `skipped_builtin` and `skipped_conversion` in `graph --stats`: call expressions that are predeclared builtins or type conversions and are therefore not stored as edges (D-073). Since S2-09 they are the only non-stored counters: the invariant is `call sites = stored rows + skipped` (no `deferred_*` counter remains).
- **Function value**: a call through a function-typed local, parameter or closure variable, or a package-level function variable (a package-level `var`/`const` whose written type is a function type such as `func()`). tree-sitter cannot resolve the target, so the call is stored `unresolved` with reason `func_value` and kind `func_value`, never `no_match` (spec story 59). A package-level declared `func` stays Rule 1 `exact`; only a variable of function type is a function value.
- **Rule 5 (unknown receiver)**: a selector call on a still-unknown receiver is looked up among every method of that name in the caller's package only: one is `name_only` (a guess with a callee), several are one `ambiguous` row per candidate, none is `unresolved` with reason `unknown_receiver` (spec story 56). Cross-package widening is not done.
- **Embedded-struct promotion is unseen**: methods promoted from an embedded struct are never recorded, so Rule 3 does not resolve them (the receiver's own method set only) and Rule 5 treats such a receiver as unknown; Rule 4's candidates likewise do not see promoted methods (spec story 60).
- **Declared-name index**: the in-memory index of every indexed package's package-level declared names (types, functions, variables, constants), built by scanning each indexed file once, so a call to a declared named type (including a non-struct type such as `type Foo int`) is recognised as a conversion rather than a missing identifier, and an import path absent from it is `external` (spec story 101).
- **Rule 4 candidate**: a concrete indexed type (value or pointer receiver) declaring every method name of the called interface; interfaces are excluded, signatures are not compared, and methods promoted from embedded structs are not seen (D-075). Same-package embedded interfaces are expanded recursively with a cycle guard; a cross-package or unresolvable embedded interface contributes only the names known, so the candidate set is a superset and the call site is counted in `interfaces_partial`. An interface with no known method name yields no candidates and, since S2-08, stores no Rule 4 row and falls through to Rule 5. A known interface stores one `ambiguous` `interface_method` row per candidate up to `MaxInterfaceCandidates` (50, D-075); more than the cap stores one `unresolved` `candidates_capped` row; candidates but none declaring the called name stores one `unresolved` `no_match` row, so the call site is always accounted for.
- **candidates_capped**: the unresolved reason (D-073) stored once for an interface call site whose Rule 4 candidate count exceeds the cap N (`MaxInterfaceCandidates`, 50): `resolution='unresolved'`, `unresolved_reason='candidates_capped'`, `callee_id NULL` and `callee_raw` kept (D-075).
- **Graph fingerprint**: `files.graphed_symbols_fp`, a hash of the indexed symbol set plus the resolver version; a file is stale when it differs or when `graphed_sha <> sha` (D-076).
- **Call site**: one call expression in a function body; identified for storage by `(caller, callee_raw, call_line)`.
- **Call kind**: `func`, `concrete_method`, `interface_method`, `func_value` (or `unknown` for tree-sitter before resolution).
- **Scored universe**: edges whose caller and callee are both in the slice; the only edges counted in call-graph precision and recall (D-074).
- **Ground-truth graph (GT)**: VTA call graph from `go/packages` over the slice, `edges.source='gopackages'`; evaluation only.
- **DEV / TEST**: 15 queries used for all tuning / 35 queries frozen by hash, each configuration run once.
- **Primary / secondary label**: relevance grade 2 / 1.
- **Frozen**: TEST file committed with its sha256 in `eval/queries.test.sha256` (D-010).
- **Build context**: `GOOS=linux GOARCH=amd64 CGO_ENABLED=0`, identical in `walk` and `callgraph-gt` (D-058).
- **B0**: BM25 keyword baseline. **A0..A4, A3n, A2-3B, E1, E2, M1**: configurations in [eval-protocol.md#configurations](eval-protocol.md#configurations).
- **ANN overlap@10**: agreement between HNSW and exact search top-10 ([eval-protocol.md#ann-overlap](eval-protocol.md#ann-overlap)).
- **MRL**: Matryoshka representation learning; vectors can be truncated and re-normalized.
- **Prompt version**: string stored with every cached or summarized LLM output; part of the cache key.
- **Overnight run**: the pausable function-level summarization run launched at the end of S1.
- **Candidate slice**: the `.go` file set `walk` selects under the four slice path prefixes after exclusions, before the freeze. It becomes the **Slice** once the drop list is applied and it is frozen with its hash (D-005).
- **Drop list**: the ordered subpath prefixes removed whole from the candidate slice to fit the compute budget; recorded at the freeze.
- **Eligible function**: an in-slice `func` or `method` symbol with a body of at least 3 lines, signature line excluded (D-014). Function literals are not symbols. A **skipped function** is an in-slice func or method below that threshold.
- **Raw calls**: call-expression text as written, per symbol, used only as summary-prompt input (D-019); never read by the S2 graph.
- **Qualified name**: the globally unique symbol name: package path plus `Name` or `Receiver.Name`, with `#n` appended from the second duplicate in a package, ordered by `(path, start_line)`.
- **12-month yield / 18-month extension yield**: counts of merged PRs usable as semantic eval queries, counted after every automatable filter, in the 12 months before the pinned tag and the further 6 months; their sum must be at least 30 at the freeze and is recomputed on the frozen slice. (S4 pool "tiers" are a separate, later notion.)
- **Quality gate**: the author's review of 30 seeded summaries from a 200-row sample before the overnight run; at most 3 bad passes (D-068).
- **ci-local**: `make ci-local`, the local mirror of `ci.yml` used until the owner pushes (D-063).
- **Gate**: a handoff sprint (S10, P2-S10) after which the agent stops and waits for the author's explicit approval.

## Phase 2
- **lodestone**: the Phase 2 tool (D-034); binary `cmd/lodestone`.
- **Default mode**: no generative model; search, find, callers, callees, MCP tools.
- **Heavy mode**: opt-in chat and summaries with a bigger model (Ollama or managed download).
- **Store interface**: the abstraction with Postgres (benchmark) and SQLite (tool) implementations.
- **Focus stack**: per-session list of recent symbols and result lists used for follow-ups without an LLM.
- **Tier 1 language**: Go, TypeScript/JavaScript, Python, Java (symbols + heuristic call graph); other text languages use fallback chunking only.
- **Model manager**: downloads, checksum-verifies, caches and probes GGUF models.
- **Compact vectors**: MRL-truncated, int8-quantized vectors stored as BLOBs.
- **Physical footprint**: macOS memory metric used for all memory claims (D-038).
- **Parity**: Phase 2 default mode versus A3n and A1 on the same queries.
- **Smoke test**: small pinned-repo sanity check for other languages; not a benchmark.
