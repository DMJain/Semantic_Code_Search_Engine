# S3 - Chunks, headers, embeddings, baseline search

Status: ready-for-agent

Sources: S3 grill (three rounds, owner confirmed with corrections), decisions D-078 to D-084 and the amendments to D-015, D-027, D-028, D-081, `docs/plan/sprints/S3-chunks-embeddings-baseline.md` (to be rewritten from this spec), `docs/plan/architecture.md` (stage chunk, stage embed, vector indexes, ollama requests, result contract).

## Problem Statement

The pipeline stops at symbols and a call graph. There is nothing yet to retrieve: no chunks, no lexical text, no vectors, no search. Every later sprint (the eval harness in S4, summaries in S5, the router and fusion in S6) needs a retrieval baseline to measure against, and the baseline has to be fair. A0 (raw code) versus A1 (code with a context header) is only meaningful if the two arms differ in nothing but the header, if no chunk silently loses its vector in one arm and not the other, if the approximate index can be shown not to bend the result, and if a token-limit failure on the second embedding model (nomic) cannot surface after the chunks are frozen and S4 to S7 are built on them.

Today the owner cannot answer: how many slice files have no chunk and so can never be returned, whether the chunk and header sizes fit both models' real tokenizers, whether the HNSW index agrees with exact search, or what a plain semantic query returns.

## Solution

`indexer chunk` splits every function, method, struct and interface of the whole filtered repo into chunks (large functions into parts, a struct with its same-file constructor into a group chunk when the pair is small), attaches a context header built from the call graph, and fills identifier-split lexical text. `cmd/tools nomic-fit` measures, before any vector is written, that the chunk and header sizes fit nomic's real context with a pre-committed failure rule. `indexer embed` embeds the slice's chunks in two kinds (`chunk_raw` for A0, `chunk_header` for A1, both with no title), idempotently and resumably. `indexer vindex` builds a per-model, per-kind HNSW index. A flat retriever and `indexer search --config A0|A1` return ranked slice files; `indexer ann-overlap` is the smoke gate that the index agrees with exact search. The operational embedding run is recorded in the sprint Results with the measurements D-080 and D-082 require.

After S3 the owner can run a natural-language query against A0 or A1, read the zero-chunk, degraded-header and failure counts, and trust that A1 minus A0 isolates the context header.

## Implementation Decisions

- **Chunker module.** Builds chunks from stored symbols and source text. One chunk per function or method; every struct and interface has its own chunk (signature, doc comment, body, up to the ceiling); a group chunk exists only for a struct or interface with a same-file `NewX` or `newX` constructor (or a function whose single return type is that type) when the pair is within `GroupMaxTokens` = 550, with the type's symbol as owner and the span of both declarations. A constructor in another file is never grouped; a grouped constructor appears only in the group chunk. Const/var blocks and type aliases are not chunked (v1 limitation; D-080 measures the effect).
- **Ceiling and splitting (D-078).** `ChunkMaxTokens` = 1000 and `GroupMaxTokens` = 550, estimated as `ceil(bytes/4)` in one constant, the same for every model. A function over the ceiling splits at top-level statement boundaries of its body, greedy-filling each part, every part prefixed with the signature line and a `part i/n` marker; `part_idx` starts at 0. A single statement over the ceiling is one whole part, logged and counted. The synthetic prefix lines are not counted in line spans. Chunker parameters (both ceilings and a chunker version) are hashed with the file sha into `files.chunked_sha`; `chunked_sha` decides re-splitting only.
- **Oversized statements (owner correction 1, D-082).** A whole-statement part above 1000 tokens still embeds with its header degraded while `tokens(content) <= RequestBudget - maxDocPrefixTokens`; only above that does it fail, identically in A0 and A1. `oversized_statements` and `oversized_failed` are reported separately.
- **Doc comment and line spans (D-083).** The existing S1 `doc()` rule is the only definition: contiguous lines directly above the declaration whose trimmed text starts with `//`; `/* */` excluded; markers and `//go:` directives included. `start_line = symbol.start_line - n`, with `n = 0` for an empty doc, else line count of the doc; a grouped chunk uses its first declaration. Part 0 carries the doc comment; later parts carry the signature only. Content equals the file lines `start_line` to `end_line`. The chunker reads the stored doc and does not redefine it. `chunks_with_block_comment_above` and `chunks_with_marker_lines` are reported as recorded limitations with no revisit trigger.
- **Stable ids (D-081 amendment).** Chunks upsert on `(symbol_id, part_idx)` with update-on-conflict and delete only vanished parts or removed symbols; a rerun with no source change leaves every chunk id unchanged.
- **Header builder (D-081, D-082).** Format: package import path, file path, signature, up to 5 callees, up to 5 callers, empty lists printing `none`. Callees and callers come from `edges` with `source='treesitter'` only, `exact` before `name_only`, `ambiguous` excluded, ties by name, names rendered as short qualified names. The header is recomputed for all chunks every run by one set-based query; header and `content_hash` (hash of header and content) are stored and updated only on a hash change. Degradation happens once at chunk time against `RequestBudget`: header budget = `RequestBudget - tokens(content) - maxDocPrefixTokens` (title is 0); order callers rank 5 to 1, callees rank 5 to 1, then the signature line; package and file lines never dropped; `chunks.header_degraded` smallint (0 = full) and the rendered header stored.
- **Request budget (D-078).** `RequestBudget = 0.8 x min(num_ctx over the registry)` = 1638 (nomic 2048, qwen3 4096). The pre-send check of D-015 is unchanged and remains the final guard. `num_ctx` per model is unchanged (D-062). The nomic fit failure rule can replace the budget (below).
- **Lexical text.** An identifier splitter (camelCase, snake_case, digits, acronym boundaries; tokens of length at least 2 and digit runs; the lowercased original kept; also split on underscore, dot, slash, colon, hyphen and whitespace) and a builder that returns a string for Postgres `simple` parsing. `chunks.search_tsv` is populated in Go from header and content for every chunk of the filtered repo; none may be empty. The same splitter is reused for lexical queries in later sprints.
- **`indexer chunk`.** Selects files whose chunked sha differs from the file sha and whose graph sha equals the file sha (the graph must exist). Per file transaction builds chunks, headers, content hashes, token counts (content only, prefix lines included, header excluded), line spans and lexical text; then one set-based header pass over all chunks. SIGINT finishes the current unit; rerun resumes. Prints chunk totals (in slice and outside), files re-split, chunks changed, parts above one, `oversized_statements`, `oversized_failed`, `header_degraded` count, token p50/p99/max, `chunks_with_block_comment_above`, `chunks_with_marker_lines`, and the zero-chunk figures (D-080): `zero_chunk_files_total`, `zero_chunk_files_with_decls`, `zero_chunk_files_no_decls`, each also as a fraction of the 876 slice files.
- **Zero-chunk trigger (D-080).** If `zero_chunk_files_with_decls` is at least 18 (2% of 876), a residual-chunk ticket is added before the embedding run: one chunk per file of its uncovered top-level const/var/type-alias declarations, statement-aligned, split at the ceiling. The measurement never uses the mined query file sets (TEST pool). Results state that B0 indexes whole files (`architecture.md` keyword baseline) and so can return files that A0 and A1 cannot.
- **Migration 00006.** Adds `embeddings.input_hash` (not null, default empty), a unique key on `(target_kind, target_id, model)`, `files.chunked_sha`, `chunks.start_line` and `chunks.end_line` (not null, default 0), `chunks.header` (if absent), `chunks.content_hash`, `chunks.header_degraded` smallint not null default 0, and `embed_failures(target_kind, target_id, model, reason, input_hash, created_at, primary key on the first three)`. The down migration reverses all of it.
- **`cmd/tools nomic-fit` (D-078).** Runs after `indexer chunk` and before the embedding run; writes nothing to `embeddings`. Samples the 200 largest in-slice `chunk_header` documents by estimate plus 200 seeded-random (`--seed 1`); one document per embed request with truncation off and nomic's context; first verifies the installed Ollama returns a prompt token count on the embed endpoint, else records accept/reject only; unloads the model after. Writes a JSON record with `n`, `accepted`, `rejected`, `ratio_p50`, `ratio_p99`, `ratio_max`, `est_max`, `real_max`, model and Ollama version under the bench results folder. Failure rule fixed before data: any rejection, or `ratio_max x RequestBudget > 0.95 x 2048`, sets `RequestBudget = floor(0.95 x 2048 / ratio_max)`, then re-run chunk and the fit check, all before the embedding run and S4; a second failure stops. Success: `rejected = 0` and `ratio_max x 1638 <= 1945`. The outcome line in D-078 is filled when run.
- **`indexer embed` (D-079, D-081, D-082).** Flags: model (default the configured embedding model), kinds (`chunk_raw`, `chunk_header`), a limit, a retry-failed flag. Unknown model is a startup error; the existing probe runs and aborts on failure. Begins with one transaction deleting orphan vectors of the two chunk kinds only, printing `orphans_deleted`. Work list per kind, ordered by chunk id: in-slice chunks without a vector for `(kind, id, model)` or with a different `input_hash`. Document text: `chunk_raw` = content; `chunk_header` = header plus content; no title for either (D-079); summary kinds keep titles. Input hash: `chunk_raw` = H(model, template, content); `chunk_header` = H(model, template, header, content). Batches of 32 through the existing embedder, each batch one transaction with upsert on the unique key. Items above `RequestBudget` are not sent (`too_large`); an input-too-long reply records `truncated` and retries that batch's items one by one; a wrong-dimension response is rejected. A failure is skipped only while its stored hash matches the current input hash. Failures above 1% of in-slice chunks are a STOP, raised and not worked around. The existing prefix registry, normalization and probe are wired, not rebuilt.
- **`indexer vindex`.** Creates `CREATE INDEX IF NOT EXISTS` per `(model, kind[, dim])` as a partial HNSW expression index on the cosine operator class (parameters m=16, ef_construction=128), with model and kind literals validated against the known models and the kinds enum before being inlined; dimension defaults to the registry dimension; idempotent; prints the index size and notes the memory setting used for the build.
- **Flat retriever and result contract (D-039, D-084).** Result is `{File, Score, Source, Evidence}`; `Source` is `flat_raw` (A0) or `flat_header` (A1). A shared collapse helper applies, in order: slice filter, best-score-per-file with all hits kept, stable sort by score descending then path ascending, cut to the limit. The flat retriever, in one transaction, sets the search width to at least `ChunkFetch` = 100 and fetches 100 chunks by `score = 1 - (vec <=> q)`, with model and kind literals validated and inlined; then collapses. Hit is `{Kind, ChunkID, File, StartLine, EndLine, Score}`; evidence per file is every fetched hit ordered by score descending then chunk id ascending. Fewer than k distinct files sets `short_result`; no refetch. The query is embedded once.
- **`indexer search`.** `--config A0|A1`, `--limit` (default 10), a query. Prints rank, score (four decimals), path, line range and the signature line of the best chunk's first declaration, tab separated. Exit 0 on success; exit 2 when stored vectors for the config's `(model, kind)` are fewer than in-slice chunks less current-hash failures, printing `have N, want M` on stderr; exit 3 is reserved for the overlap gate. No other flags.
- **`indexer ann-overlap` (D-027).** `--model`, `--kind`, `--queries <file|probe>`, `--ef` (a single value or a list, maximum 1000). `probe` builds 30 seeded queries (seed 5) from first sentences of doc comments of random in-slice functions, at least 12 words each. For each query compares the HNSW top 10 with exact brute force (index disabled) under the same slice filter, both with a 200-row fetch and search width at least 200, at chunk level (the gate) and at file level (reported). Prints mean and min per level and one row per width; chunk-level mean below 0.95 exits with status 3 and prints `tune ef_search`. The probe is a smoke gate and optimistic; the binding gate is the DEV run in S4.
- **Eval contract carried to S4 (D-027 amendment).** HNSW serves every config. S4 reports chunk-level and file-level overlap at the chosen width. DEV parity: A0 and A1 Recall@10, nDCG@10 and MRR identical under `--exact` and HNSW, else raise the width until identical or overlap is 100%, recorded in D-028. `--exact` is a sequential scan with the same predicates, DEV only, refused with `--final`. Result JSON records `search`, `ef_search`, `overlap_chunk@10`, `overlap_file@10` and `short_results`.
- **Run coordination.** The summary run is paused (S1 procedure, step 2) before `nomic-fit` and before the embedding run, each with its own pause and resume; before each, `ollama ps` shows no loaded model and the output goes in Results; `nomic-fit` unloads its model; resume follows each step; ROADMAP now says "pause only for S3 nomic-fit and S3-T09 embedding". The embedding run does not start until `nomic-fit` passes and the D-080 outcome is recorded. The embedding run logs the qwen3 per-item real-versus-estimate ratio and reports it without changing `ChunkMaxTokens`.
- **Tickets and seams.** Ticket order follows dependencies: chunker, group, header, migration, splitter, chunk command, then (conditional residual chunk), `nomic-fit`, embed, vindex, operational run, retriever, search CLI, overlap tool. The conditional residual-chunk ticket exists only if the D-080 trigger fires and sits before the embedding run.

## Testing Decisions

- **What makes a good test here.** Assert external behavior only: rows and columns in a real database, command output and exit codes, the shape of result JSON and the requests a fake Ollama server receives. No assertions on private helpers. Golden files are never rewritten by `make test` or CI; regeneration is a manual flag. Every database test uses its own throwaway database (D-066) and fails instead of skipping.
- **Seam 1 - `indexer chunk` over a committed fixture tree and real Postgres.** Asserts chunk rows for each case (small function, long function split into parts each at most 1000 except one oversized statement, one giant switch, generic function, struct with and without constructor, constructor over 550 combined, constructor in another file, grouped constructor not also its own chunk), the signature on every part, line spans with `content == lines[start_line..end_line]` (1-based), doc-comment cases (`/* */` above a function gives an empty doc and `start_line` at the function line; a marker plus `//` doc gives `start_line` at the marker; a detached comment with a blank line is excluded; an adjacent `//go:noinline` is included), header text (top 5 in the specified order with exact before name_only and ambiguous excluded, `none` for empty lists), header degradation (budget 0 gives package and file only with `header_degraded > 0`; order callers, callees, signature), the oversized-statement rule (still embeds below the content limit, `oversized_failed` counted above it), `search_tsv` never empty and matching `to_tsquery('simple','pod')`, idempotency (`0 files re-split, 0 chunks changed`, every chunk id unchanged), interrupt-and-rerun equals an uninterrupted run, changing the ceiling re-splits all files, deleting one edge changes `content_hash` for exactly the two affected header chunks, and the printed counters including the zero-chunk figures and marker and block-comment counts. The pure splitter, the token estimate and the identifier splitter get table and fuzz tests (`schedulePod`, `HTTPServer`, `pod_backoff`, empty and unicode input).
- **Seam 2 - `indexer embed` against a fake Ollama server and real Postgres.** Asserts batching (32), that an item over the request budget is never sent (the server records zero requests for it) and gets a `too_large` failure, that an input-too-long reply records `truncated` and retries items one by one, that a wrong-dimension response is rejected, the input hashes by kind (a graph change re-embeds the header vector only), idempotency (rerun inserts 0), orphan cleanup (deleting one chunk gives `orphans_deleted = 2` and a left join of embeddings on chunks shows no row without a chunk), a stale-hash failure is retried and a matching one skipped, no chunk or summary of a non-slice file is ever embedded, the failure sets of `chunk_raw` and `chunk_header` are identical per model, the 1% STOP, and both chunk kinds render with no title (the nomic no-title render of the fixed input still hashes to the pinned value; a header render starts with the document prefix then the first header line). A guarded live run records vector dimension and norms. Unit tests cover the migration up/down round trip and the unique key.
- **Seam 3 - `cmd/tools nomic-fit` against a fake Ollama server.** Asserts sample selection (200 largest plus 200 seeded-random, deterministic under the seed), one document per request, nothing written to `embeddings`, the JSON record fields, the fallback when no token count is returned, the budget replacement computed by the failure rule on a rejection or an over-limit ratio, and the second-failure stop. The real run is recorded evidence.
- **Seam 4 - `indexer vindex`, the flat retriever, `indexer search` and `indexer ann-overlap` over fixture vectors and real Postgres.** Asserts that `EXPLAIN` shows the expected index on a 200-row fixture with the scan setting forced and the same plan after ten runs through the pool (the partial-index predicate matches); the collapse helper (two chunks of one file give one result at the best score with both in evidence, ties, empty, limit, slice filter before dedupe and cut: 12 hits with the 10 best out of slice return the 2 in-slice, not an empty list); that 15 chunks from 2 files ranked first plus 20 more files return 10 distinct files, that the search width of at least `ChunkFetch` is asserted, and that fewer than k files sets `short_result`; the CLI output format, exit 0 on success, exit 2 with `have N-1, want N` after deleting one vector, and a non-zero exit when a config has no vectors; the overlap computation, exit 3 with `tune ef_search` below 0.95, and one row per width for a sweep.
- **Recorded evidence, not automated tests.** The real-corpus steps (whole-repo chunk run, the zero-chunk and marker figures, the nomic fit run, the embedding run with throughput and qwen3 ratio, index builds and sizes, the overlap run and chosen width, the `ollama ps` pastes, the summary-run pause and resume) record the command, trimmed output and counts in the sprint Results.
- **Shared infrastructure.** No new raw skips; the no-skip rule of `make test`, `ci-local` and CI stays.
